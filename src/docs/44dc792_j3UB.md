# UniStack SQL Abstraction Layer (DataSet)

## Overview

The `DataSet` ORM-like abstraction layer provides a safe, intuitive API for building SQL queries without writing raw SQL strings. It prevents SQL injection vulnerabilities through parameterized queries and offers a fluent, chainable interface for composing complex database operations.

## Features

- **Fluent API** - Method chaining for readable query construction
- **Type-Safe Parameters** - Parameterized queries prevent SQL injection
- **Query Builder Pattern** - Build complex queries step by step
- **Static CRUD Operations** - create(), update(), delete() for direct mutations
- **Chainable Methods** - where(), limit(), offset(), orderBy()
- **SQL Generation** - Get safe parameterized SQL with `toSQL()`

## Basic Syntax

### SELECT All Records

```javascript
// Get all records from a table
const result = DataSet.all('users').toSQL();
// Returns: { query: 'SELECT * FROM users', params: [] }
```

### Filtering with WHERE

```javascript
// Single condition
const result = DataSet.all('users')
  .where({ status: 'active' })
  .toSQL();
// Returns: { 
//   query: 'SELECT * FROM users WHERE status = ?',
//   params: ['active']
// }

// Multiple conditions (AND)
const result = DataSet.all('users')
  .where({ status: 'active', role: 'admin' })
  .toSQL();
// Returns: {
//   query: 'SELECT * FROM users WHERE status = ? AND role = ?',
//   params: ['active', 'admin']
// }
```

### Pagination with LIMIT and OFFSET

```javascript
// Get 10 records starting from position 20
const result = DataSet.all('users')
  .limit(10)
  .offset(20)
  .toSQL();
// Returns: {
//   query: 'SELECT * FROM users LIMIT 10 OFFSET 20',
//   params: []
// }
```

### Sorting with ORDER BY

```javascript
// Sort ascending
const result = DataSet.all('users')
  .orderBy('created_at', 'ASC')
  .toSQL();
// Returns: {
//   query: 'SELECT * FROM users ORDER BY created_at ASC',
//   params: []
// }

// Sort descending
const result = DataSet.all('users')
  .orderBy('created_at', 'DESC')
  .toSQL();
```

### Chaining Multiple Operations

```javascript
// Complex query with multiple conditions
const result = DataSet.all('users')
  .where({ status: 'active' })
  .where({ role: 'admin' })
  .orderBy('created_at', 'DESC')
  .limit(5)
  .toSQL();

// Returns: {
//   query: 'SELECT * FROM users WHERE status = ? AND role = ? ORDER BY created_at DESC LIMIT 5',
//   params: ['active', 'admin']
// }
```

## CRUD Operations

### CREATE (Insert)

```javascript
const query = DataSet.create('users', {
  name: 'John Doe',
  email: 'john@example.com',
  status: 'active'
});
// Returns: {
//   query: 'INSERT INTO users (name, email, status) VALUES (?, ?, ?)',
//   params: ['John Doe', 'john@example.com', 'active']
// }
```

### UPDATE

```javascript
const query = DataSet.update('users', 
  { status: 'inactive' },  // New values
  { id: 42 }               // WHERE condition
);
// Returns: {
//   query: 'UPDATE users SET status = ? WHERE id = ?',
//   params: ['inactive', 42]
// }

// Multiple updates
const query = DataSet.update('users',
  { status: 'inactive', updatedAt: '2024-01-15' },
  { role: 'guest' }
);
// Returns: {
//   query: 'UPDATE users SET status = ?, updatedAt = ? WHERE role = ?',
//   params: ['inactive', '2024-01-15', 'guest']
// }
```

### DELETE

```javascript
const query = DataSet.delete('users', { id: 42 });
// Returns: {
//   query: 'DELETE FROM users WHERE id = ?',
//   params: [42]
// }

// Delete all records matching condition
const query = DataSet.delete('sessions', { expires_at: null });
// Returns: {
//   query: 'DELETE FROM sessions WHERE expires_at = ?',
//   params: [null]
// }
```

## SQL Injection Prevention

DataSet automatically uses parameterized queries to prevent SQL injection:

```javascript
// UNSAFE (bad - DO NOT DO THIS):
const unsafeSQL = `SELECT * FROM users WHERE id = ${userInput}`;

// SAFE (good - what DataSet does):
const safeQuery = DataSet.all('users').where({ id: userInput }).toSQL();
// Always generates: { query: 'SELECT * FROM users WHERE id = ?', params: [userInput] }
```

The `?` placeholders are replaced with actual values by the database driver, preventing malicious SQL injection.

## API Reference

### DataSet.all(tableName: string): DataSet

Returns a new DataSet instance for querying the specified table.

```javascript
const ds = DataSet.all('orders');
```

### .where(conditions: Record<string, any>): DataSet

Adds a WHERE clause with the specified conditions (AND logic). Chainable.

```javascript
const ds = DataSet.all('users')
  .where({ country: 'US' })
  .where({ age: 18 });
// Generates: WHERE country = ? AND age = ?
```

### .limit(count: number): DataSet

Limits the number of returned records. Chainable.

```javascript
const ds = DataSet.all('users').limit(50);
// Generates: LIMIT 50
```

### .offset(count: number): DataSet

Skips the specified number of records (for pagination). Chainable.

```javascript
const ds = DataSet.all('users').limit(10).offset(20);
// Gets records 21-30
```

### .orderBy(column: string, direction?: 'ASC' | 'DESC'): DataSet

Sorts results. Chainable. Defaults to ASC.

```javascript
const ds = DataSet.all('users').orderBy('email', 'ASC');
// Generates: ORDER BY email ASC
```

### .toSQL(): { query: string; params: any[] }

Executes the query building and returns the SQL string and parameters array.

```javascript
const { query, params } = DataSet.all('users')
  .where({ status: 'active' })
  .toSQL();

// Use with your database driver:
// const rows = await db.query(query, params);
```

### DataSet.create(table: string, data: Record<string, any>): { query: string; params: any[] }

Builds an INSERT query.

```javascript
const { query, params } = DataSet.create('users', {
  name: 'Alice',
  email: 'alice@example.com'
});
```

### DataSet.update(table: string, updates: Record<string, any>, where: Record<string, any>): { query: string; params: any[] }

Builds an UPDATE query.

```javascript
const { query, params } = DataSet.update('users',
  { status: 'inactive' },
  { id: 1 }
);
```

### DataSet.delete(table: string, where: Record<string, any>): { query: string; params: any[] }

Builds a DELETE query.

```javascript
const { query, params } = DataSet.delete('users', { id: 1 });
```

## Real-World Examples

### Pagination API

```python
def getUsers():
  page = 1  # From request params
  pageSize = 10
  offset = (page - 1) * pageSize
  
  query = DataSet.all('users')
    .where({status: 'active'})
    .orderBy('created_at', 'DESC')
    .limit(pageSize)
    .offset(offset)
    .toSQL()
  
  return query
```

### Search with Multiple Filters

```python
def searchProducts():
  query = DataSet.all('products')
    .where({status: 'published'})
    .where({price_gte: 10})
    .orderBy('popularity', 'DESC')
    .limit(20)
    .toSQL()
  
  return query
```

### Batch Operations

```python
def createUsers():
  # Create multiple users
  results = []
  for user in users:
    query = DataSet.create('users', user)
    results.append(query)
  
  return results
```

### Dashboard Statistics

```python
def getAdminStats():
  # Get counts with proper filtering
  activeUsers = DataSet.all('users')
    .where({status: 'active'})
    .toSQL()
  
  recentOrders = DataSet.all('orders')
    .orderBy('created_at', 'DESC')
    .limit(100)
    .toSQL()
  
  return {
    'activeUsersQuery': activeUsers,
    'recentOrdersQuery': recentOrders
  }
```

## Best Practices

### 1. Always Use Parameters

[OK] Good:
```javascript
DataSet.all('users').where({ id: userId }).toSQL()
```

[Cross] Bad:
```javascript
`SELECT * FROM users WHERE id = ${userId}` // SQL injection risk
```

### 2. Chain Logically

[OK] Good:
```javascript
DataSet.all('users')
  .where({ status: 'active' })
  .orderBy('created_at', 'DESC')
  .limit(10)
  .toSQL()
```

[Cross] Bad:
```javascript
DataSet.all('users').limit(10).where({ status: 'active' }).toSQL()
// Logically confusing order
```

### 3. Clear Variable Names

[OK] Good:
```javascript
const activeUserQuery = DataSet.all('users')
  .where({ status: 'active' })
  .toSQL();
```

[Cross] Bad:
```javascript
const q = DataSet.all('users').where({ s: 'a' }).toSQL();
```

### 4. Handle Database Results

```python
def getUsers():
  { query, params } = DataSet.all('users').where({status: 'active'}).toSQL()
  
  # Execute query with your database driver
  results = database.query(query, *params)
  return results
```

## Migration from Raw SQL

### Before (Raw SQL)

```python
def getActiveUsers():
  query = f"SELECT * FROM users WHERE status = '{status}'"  # Unsafe!
  return query
```

### After (DataSet ORM)

```python
def getActiveUsers():
  query = DataSet.all('users').where({'status': 'active'}).toSQL()
  return query
```

## Performance Considerations

- **Parameterized Queries** - Enables database query plan caching
- **Proper Indexing** - Index columns used in WHERE and ORDER BY clauses
- **Pagination** - Always use limit() and offset() for large data sets
- **Connection Pooling** - The generated server supports connection pooling
